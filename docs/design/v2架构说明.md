# OCC 架构说明（OpenCode v2）

> 本文描述重构后的分层与关键约束。改动涉及以下任一约定时应同步更新本文。

## 1. 分层

```
UI (features/**, components/**)
  ↓ 只调用 api/* 与 hooks/*
hooks/**          业务编排（会话、事件、输入、布局）
  ↓
api/**            对 @opencode/client 的分层封装
  ↓
storage/**        本地持久化（单一数据源）
store/**          进程内状态（可订阅）
types/api,types/domain   类型
```

**硬约束**

- UI 不直接 import `@opencode/client`；只通过 `api/*`（`getV2Client`）访问。
- 持久化只能经由 `storage/createStore`，不允许组件里直接 `localStorage.setItem`
  业务键（例外：纯 UI 临时态，且需在注释里说明为什么不落盘）。
- 每台服务器的数据必须**显式**携带 `serverId`；不存在“当前服务器”的隐式回退。

## 2. 协议

OCC 只支持 OpenCode **2.x**。

- 健康检查：`GET /api/info`（v1 的 `/global/health` 在 v2 会被 SPA 接管返回 HTML）。
- 检测到 v1 服务器时直接报错，不做降级。
- v2 没有的能力在 `api/*` 里显式降级并注明原因，例如：
  - 仓库级文件状态 → 空数组（状态来自 `vcs.status` / `session.diff`）
  - 全文搜索 → 空结果（`file.find` 只搜文件名）
  - MCP resources 列表 → 空集合（变化由 `mcp.resources.changed` 事件推送）
  - `instance.dispose` / MCP OAuth → no-op
  - 无 `fields` 的原生 question → 返回 `false`（不做空答案提交）

## 3. 存储

- `createStore`：Zustand-free + Zod 校验，提供 `commit / applyRemote / rebind / schema`。
- 每个 store 绑定明确的 `serverId`；`rebind` 用于切换服务器。
- 可同步的范围仅 6 类：项目列表、置顶会话、置顶消息、已读水位、项目最近使用、主题。
  个性化/外观设置**不同步**。
- 推送是增量的（相对基线的脏键 diff）；删除用 tombstone 触发全量键推送。
- 首次同步成功后执行一次服务端旧键清理（`syncCleanup.ts`）。

## 4. 事件

- 单一 SSE：`@opencode/client` 的 `event.subscribe()`（AsyncIterable）。
- 事件名到内部事件的映射集中在 `api/v2/events.ts`；**只有那里**知道 v2 原名。
- `PartDeltaPayload` 等载荷类型是 v2 原生形状（`assistantMessageID` + `ordinal`），
  需要按 part 索引的消费方（`messageStore`）在 `useGlobalEvents` 边界做转换。
- 轮询节奏：SSE 已连接 60s，断开 15s。

## 5. 性能约定

- **大 diff**：行计算在 `utils/diffLines.ts`；超过 60k 字符推迟到空闲帧，先渲染加载态。
- **多 diff 卡片**：`ContentBlock` 用 IntersectionObserver 把关，离屏块不计算、不挂载。
- **消息适配**：v2 消息分页用 `adapterMessagePageAsync` 分块执行（每 ~6ms 让出）。
- **语法高亮**：`utils/codeCache` 提供进程级共享 LRU，跨组件复用。
- **虚拟列表**：行相等判定不比较 `virtualItem.size`（测量回写不应触发重渲染）。
- **长列表**：文件树节点使用 `content-visibility: auto` 跳过离屏布局/绘制。
- **日志**：生产路径用 `logger`，`console.*` 只允许出现在 dev 分支或 worker 内。

## 6. 组件

- `App.tsx` 只做编排：路由、pane、弹窗；具体逻辑在 `useAppShell` /
  `useAppKeybindings` / `usePaletteCommands` / `useAppDialogs`。
- 侧栏：`SidePanel` 负责布局，状态在 `useSessionSelection` / `useProjectGroups` /
  `useMissingSessionFetch`，列表渲染与排序在 `FolderRecentList` + `useFolderList`。
- 输入框：触发态在 `useMentionTrigger` / `useSlashTrigger`，粘贴策略在
  `useLargePaste`，尺寸预算在 `inputMetrics`。
- 样式词汇：交互态用 `utils/interaction`，控件尺寸/语义色用 `utils/controlStyles`；
  业务代码不再手写 `hover:bg-*` 组合。
