# v2 原生全量适配计划（v2 分支）

状态：**计划，待实施**
范围：`src/api/*`、`src/types/api/*`、`src/types/domain/*`（新建）、`src/api/v2/*`、`src/api/clientFacade.ts`、`src/api/sdk.ts`、`src/api/events.ts`、`src/hooks/useGlobalEvents.ts`、`src/store/messageStore.ts` 等
约束：**可破坏性适配**（v2 分支可自由重构，不要求兼容 v1 运行期，但 UI 层行为必须保持一致）

---

## 一、目标

让 **v2 成为第一公民**：前端直接用 `@opencode/client`（v2 原生）的类型与调用，删除 `clientFacade.ts`（v1→v2 适配层）与 `src/api/v2/*` 的 v1 适配函数。前端建立自己的**领域类型层（Domain Types）**，UI 只依赖这层，v2 提供映射。

```
前端 UI / store ──► 领域类型层 (src/types/domain) ◄── 各 api 模块返回 DTA
                         ▲
                         └── v2 原生 @opencode/client 直接映射（无 v1 适配）
```

## 二、调研结论（已完成）

### 2.1 v2 API 覆盖度

v2 协议（`@opencode/protocol`，30 个 group）**覆盖前端全部需求**，无功能缺口。官方客户端 `@opencode/client@2.0.28` 已安装。

### 2.2 前端 v1 调用点（20 个 api 模块）

| 模块 | SDK 调用数 | 关键 v1 形状 |
|---|---|---|
| session.ts | 17 | `directory`、`{info,parts[]}`、page/limit 分页 |
| message.ts | 4 | `session.messages`、`X-Next-Cursor` header、超大 limit(100000) |
| client.ts | 5 | `config.providers`、`project.current/list/initGit`、`path.get` |
| config.ts | 5 | `config.get/update`、`global.config.*`、`config.providers` |
| file.ts | 5 | `file.list/read/status`、`find.files/text` |
| mcp.ts | 7 | `mcp.status/add/connect/disconnect/auth`、`experimental.resource.list` |
| vcs.ts | 2 | `vcs.get/diff` |
| worktree.ts | 4 | `worktree.list/create/remove/reset` |
| pty.ts | 5+裸HTTP | `pty.*`、WS connect URL、stream-token |
| global.ts | 2 | `global.health`、`instance.dispose` |
| command.ts / skill.ts / agent.ts | 各1-2 | `command.list`、`app.skills`、`app.agents` |
| permission.ts | 6 | `permission.*`、`question.*` |

### 2.3 UI 层类型绑定（17 个 src/types/api/*.ts）

全部从 `@opencode-ai/sdk/v2/client` 导入 v1 类型。核心自定义结构：
- `MessageWithParts` = `{info: Message, parts: Part[]}`（12 种 part 联合）
- `SessionStatusMap`、`FileDiff`、`MCPResourceMap`、`TodoItem`、`NextToolSettledPayload`

### 2.4 v1/v2 关键形状差异

| 维度 | v1 | v2 |
|---|---|---|
| 目录定位 | `directory` | `location:{directory}` |
| 消息结构 | `Message` + `Part[]`（`parts`） | `SessionMessage.Info`，assistant 用 `content[]`（text/reasoning/tool） |
| 消息事件 | `message.updated`/`part.delta` 等 | **无 message.* 事件**，改用 `session.text.delta`/`reasoning.delta`/`tool.*`/`step.*` + `assistantMessageID` + `ordinal` |
| 流式文本 | part index/type | `session.text.delta` 带 `assistantMessageID` + `ordinal` |
| 分页 | page/limit | 不透明 `cursor`（`{previous,next}`），limit 上限 200 |
| 模型引用 | `{providerID, modelID}` | `{providerID, id}` |
| prompt 入参 | `parts[]` | `{text, files[], agents[], skills[]}` |
| 权限/表单 | question 体系 | `session.permission.*` + `session.form.*` 一等公民 |
| 会话状态 | `SessionStatus` 字段 | 无字段，靠事件 + `session.active()`/`outcome` |
| 补拉历史 | `session.messages` | `session.messages` + `session.log`（Stream） |

### 2.5 现有 v2 适配层（要删除的）

- `clientFacade.ts`（538 行）：`createV2Facade` 把 v2 适配回 v1 形状
- `src/api/v2/adapt.ts`、`entities.ts`、`message.ts`、`session.ts`：v1 适配函数
- `src/api/v2/events.ts`：`v2EventToGlobalEvent` 映射到 v1 `EventTypes`
- `src/api/sdkV2.ts`：v2 client 获取

## 三、改造方案

### 3.1 建立领域类型层 `src/types/domain/`

定义前端真正需要的模型，UI 与 store 只依赖这层。**直接采用 v2 原生形状**（不迁就 v1）：

```
domain/session.ts    SessionInfo（location.directory、outcome、time）
domain/message.ts    ChatMessage（type 标签联合 + content[]）+ 流式增量类型
domain/agent.ts      AgentInfo
domain/model.ts      ModelInfo / ProviderInfo
domain/command.ts    CommandInfo（name/description）+ 合并 skill 的 slash 命令
domain/permission.ts PermissionRequest / PermissionReply
domain/form.ts       FormInfo / FormDetail
domain/file.ts       FileSystemEntry / FileMatch
domain/vcs.ts / pty.ts / worktree.ts / config.ts ...
domain/event.ts      前端事件类型（ChatEvent，独立于 v1 EventTypes）
```

**关键：消息模型采用 v2 `content[]` 而非 v1 `parts[]`。** 这是改动最大的点，`messageStore.ts`、所有消息渲染组件都要改。

### 3.2 各 api 模块改为直接返回 DTA（v2 原生调用）

每个 `src/api/*.ts` 内部用 `@opencode/client` 原生方法 + DTA 映射，不再经 v1 facade：

| 模块 | v2 原生调用 |
|---|---|
| session | `client.session.list/create/get/update/remove/fork/active/interrupt/...` |
| message | `client.message.list`（cursor 分页）+ `client.session.prompt/command/skill` |
| config | `client.config.get/update` + `client.model.list` + `client.provider.list` |
| file | `client.file.list/find/read`（`fs` group）|
| mcp | `client.mcp.list/add/connect/disconnect/resource.catalog` |
| vcs | `client.vcs.get/status/diff/branch.list` |
| worktree | `client.worktree.list/create/remove/refresh`（projectID 键）|
| pty | `client.pty.*` + WS connect（`/api/pty/:id/connect`）|
| command/skill/agent | `client.command.list` + `client.skill.list` + `client.agent.list` |
| permission/form | `client.permission.*` + `client.form.*` + `session.permission.reply` |
| project/location/path | `client.project.list` + `client.location.get` |
| global/health | `client.server.info` |

### 3.3 事件系统重写（核心难点）

**删除对 v1 `EventTypes` 的依赖，建立前端自己的事件模型 `ChatEvent`。** v2 `/api/event` SSE 直接消费：

- 消息渲染不再等 `message.updated`，而是用 **`session.*` 增量事件拼装**：
  - `session.step.started`（assistantMessageID，创建消息骨架）
  - `session.text.started/delta/ended`（`ordinal` 定位，delta 累加）
  - `session.reasoning.started/delta/ended`
  - `session.tool.*`（工具状态流）
  - `session.step.ended/failed`
- 会话状态：`session.status`（idle/busy/retry）、`session.idle`、`session.execution.*`
- 补拉历史：会话打开时用 `session.messages`（cursor 分页）+ `session.log`（Stream，含 `session.message.content.updated`）
- 权限/表单：`permission.asked/replied`、`form.created/replied/cancelled`

### 3.4 删除的代码

- `src/api/clientFacade.ts`
- `src/api/sdkV2.ts`
- `src/api/v2/*`（adapt/entities/message/session/events）
- `getSDKClient` 的 facade 分支
- `src/api/v2ClientTiming.test.ts` 等针对 facade 的测试（改为针对 DTA 映射）

### 3.5 保留的 v1 能力决策

以下 v2 原生无对应，需决定 UI 层去向：
- `session.share/unshare/todo`：v2 用 `session.todo` 事件驱动（todo 数据在事件里），share 无 → UI 隐藏
- `question.*`：v2 用 Form 体系替代 → UI 渲染 Form
- `find.text`：v2 无 → UI 隐藏或降级
- `worktree.*`：v2 用 projectID 键 → 适配 project 模型
- `mcp.auth.start`：v2 用 Integration OAuth → 走 integration 流程
- `instance.dispose`：v2 无 → 移除

## 四、分阶段实施

| 阶段 | 内容 | 交付物/验证 |
|---|---|---|
| **P0 领域层** | 建 `src/types/domain/*`，定消息模型（content[]）| typecheck |
| **P1 事件/消息流** | 重写事件系统 + `messageStore` 消息拼装 | 对话可正常流式（修当前"无响应"根因）|
| **P2 会话/侧栏** | session 列表/状态/新建/归档迁移 | 侧栏正常 |
| **P3 能力模块** | 逐个迁移 config/model/mcp/file/vcs/worktree/pty/command/skill/permission/project | 各功能正常 |
| **P4 清理** | 删 facade 与 v1 适配，删相关测试 | 全量测试绿 + build |

**P1 是当前"对话无响应/无法归档"bug 的根治项**：v2 无 `message.updated`，前端却等它建骨架 → 需改用 `session.*` 事件拼装。

### 5.1 v2 沙盒验证（已落地）

由于工作主机实为 **opencode v1（1.18.32）**（`/global/health` 返回 JSON version 1.18.32，
根路径 `/session`/`/config` 返回 JSON），无法用于验证 v2 分支。验证需用真实 v2 服务器。

已用本机 **v2 沙盒**（`@opencode/cli@2.0.28`）验证：

```bash
# 安装 v2 二进制（隔离目录）
mkdir -p %TEMP%\opencode\v2-sandbox && cd %TEMP%\opencode\v2-sandbox
npm init -y && npm install @opencode/cli@2.0.28

# 启动 v2 serve（后台，Basic auth：opencode/<server password>）
& .\node_modules\@opencode\cli\bin\opencode.exe serve --hostname 127.0.0.1 --port 4099 --cors "*"
```

验证结果（`src/api/v2Sandbox.test.ts`，4 用例全过）：
- 版本探测：`v2` / `2.0.28`（`/api/info` JSON、`/global/health` HTML）
- `session.experimental.list` / `session.create`：真实契约正常
- `config.providers`：provider + model 合并（model 失败时容错降级）

```bash
# 运行（需沙盒在跑）
$env:VITE_V2_SANDBOX_URL="http://127.0.0.1:4099"
$env:VITE_V2_SANDBOX_PASSWORD="<server password>"
npx vitest run src/api/v2Sandbox.test.ts
# 无 env 时自动跳过，CI 安全
```
